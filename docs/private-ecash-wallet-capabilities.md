# Native wallet capabilities for private ecash transport

Read-only audit, 2026-09-05. Reuse native wallet send, receive and recovery. Neither a delivered payload nor a successful native process proves redemption. Do not replace existing native proof-state recovery with a second raw NUT-07 client.

## Concrete bindings

Use `cdk-cli --work-dir /wallet/cdk --unit sat --non-interactive` for every CDK invocation. Cocod clients retain `COCOD_URL=http://127.0.0.1:62626`; authenticated native HTTP calls privately read `/wallet/.cocod/credentials/current/client`. No second wallet SDK or daemon should open the existing state directory.

| Wallet/action | Exposed native binding | Input/output and effects |
| --- | --- | --- |
| CDK export | `send --mint-url URL --amount SAT` | Prepares and confirms a send, then prints a token. Default is online exact; may swap with the mint and changes local proofs/saga state. `--offline` selects offline exact/tolerance, but still changes local state. Avoid `--animate`. |
| CDK import | `receive TOKEN` | Token is a positional string. Parses token, selects its mint, calls native `wallet.receive`, swaps/redeems and updates local state. Existing mint trust is required unless explicit `--allow-untrusted` is chosen. There is **no stdin, token-file or special `-` input** in this command. Missing TOKEN selects the separate Nostr path, not stdin. |
| CDK pending/spent reconciliation | `check-pending`; `burn [MINT_URL]` | Both use the native wallet's mint proof-state checks. They mutate local records; details below. They are not token-specific passive check commands. |
| CDK local display | `balance`; `list-mint-proofs` | Display local balances/proof classifications, but CLI startup first recovers sagas. `list-mint-proofs --show-secrets` exposes secrets and is not a token-export/reissue API. |
| Cocod export | `cocod send cashu SAT --mint-url URL`; native `POST /send/cashu` body `{amount, mintUrl}` | Calls manager send prepare/execute and encodes the token. HTTP success is `{output: TOKEN}`; CLI prints the output string. Mutates wallet operations/proofs and may swap at the mint. Neither route nor CLI returns a send operation ID. |
| Cocod import | `cocod receive cashu TOKEN`; native `POST /receive/cashu` body `{token}` | CLI is positional-only: no stdin/file option. Existing native HTTP JSON body accepts the token privately without putting it in process argv or the agent request. It prepares and executes a receive; success is `{output: "Received …"}`, not a structured operation handle. |
| Cocod reconciliation observations | `cocod history --offset N --limit N`; native `GET /history?offset=N&limit=N`, limit 1–100 | Reads paginated native operation history. Entries can contain operation IDs, states **and full token/proof material**. Keep the response private; correlate exact token/proof identity and operation ID, not only amount/time. `history --watch`/`GET /events` streams history changes, not a separate proof-state oracle. |
| Cocod local totals | `cocod balance`; native `GET /balance`; existing passive `wallet_balance` | Local observation. Daemon history/balance require a running session; the existing SQLite observation can work while locked/stopped. A running daemon's background recovery can change state independently of these reads. |

## CDK recovery semantics and gaps

Before dispatching an ordinary subcommand, CLI startup opens/initializes wallet state and invokes `recover_incomplete_sagas()` for every wallet. Even `balance` and `decode-token` therefore cannot serve as strictly passive commands against the live wallet. Startup can print a recovery summary **before** a send's token, so successful send stdout is not guaranteed to contain exactly one token line. `decode-token TOKEN` prints token contents, including secrets; it decodes, not checks spent status. Use the existing passive observation when an actual read-only boundary matters. [CLI startup/dispatch](https://github.com/cashubtc/cdk/blob/d3dec24c784e8fec1fd65f853241c7a2261c7abd/crates/cdk-cli/src/main.rs#L260), [decode implementation](https://github.com/cashubtc/cdk/blob/d3dec24c784e8fec1fd65f853241c7a2261c7abd/crates/cdk-cli/src/sub_commands/decode_token.rs#L16).

`check_all_pending_proofs()` selects pending/reserved/pending-spent proofs **without an active saga association**. It queries mint state through native `check_proofs_spent`, removes spent local proofs, and leaves both UNSPENT and PENDING exported proofs pending. It does not reclaim every unspent token or interfere with active sagas. Its return is the amount still pending. Consequently, `burn`'s printed “burned” label must not be treated as an independently measured amount destroyed. `check-pending` catches per-wallet errors, prints them and can return exit 0; inspect private diagnostic evidence as well as balances. [Proof reconciliation](https://github.com/cashubtc/cdk/blob/d3dec24c784e8fec1fd65f853241c7a2261c7abd/crates/cdk/src/wallet/proofs.rs#L96), [check-pending](https://github.com/cashubtc/cdk/blob/d3dec24c784e8fec1fd65f853241c7a2261c7abd/crates/cdk-cli/src/sub_commands/check_pending.rs#L16), [burn](https://github.com/cashubtc/cdk/blob/d3dec24c784e8fec1fd65f853241c7a2261c7abd/crates/cdk-cli/src/sub_commands/burn.rs#L13).

`mint-pending` at this pin also calls `check_all_pending_proofs`; its help does not describe its implementation accurately. It is not an arbitrary paid-quote/import completion command. [Implementation](https://github.com/cashubtc/cdk/blob/d3dec24c784e8fec1fd65f853241c7a2261c7abd/crates/cdk-cli/src/sub_commands/pending_mints.rs#L5).

For interrupted export/import, retain the existing wallet and invoke its native recovery deliberately rather than retrying `send` or `receive`. Send recovery checks the original saga/proofs and either compensates, completes or preserves an unresolved operation. Receive recovery can replay its original swap request and recover outputs through native mint restore logic. This is wallet-owned recovery, not permission for transport to construct another receive mutation. [Send recovery](https://github.com/cashubtc/cdk/blob/d3dec24c784e8fec1fd65f853241c7a2261c7abd/crates/cdk/src/wallet/send/saga/resume.rs#L43), [receive recovery](https://github.com/cashubtc/cdk/blob/d3dec24c784e8fec1fd65f853241c7a2261c7abd/crates/cdk/src/wallet/receive/saga/resume.rs#L80).

The CLI command inventory has no operation-ID get/list/refresh/revoke command, no arbitrary-token spent check, and no documented exact-send token re-emission command. Library methods are not CLI capabilities. If an export committed but its private token capture was lost, a new `send` is a new debit, not retrieval. Reconcile native state; retain unknown delivery/export status when the old bytes cannot be identified.

**Large CDK import is a concrete gap:** loading a private file and expanding it into TOKEN avoids agent transcript exposure but still hits OS argument-size limits. It is not streaming. This pinned CLI cannot honestly satisfy an unbounded stdin/file consumer contract. Keep its supported binding bounded or require a separately pinned native input enhancement; do not silently substitute a second SDK operating its database.

## Cocod recovery: exposed daemon versus library

The public v1 routes cover lifecycle and administration. Cashu operations remain legacy routes, each creating a prepared operation and executing it. No operation ID or cashu idempotency key is accepted/exposed there. A receive error may be HTTP 200 with `{error: ...}`; HTTP success alone is insufficient. The CLI explicitly checks that envelope and exits 1. The cashu handlers do not wire request abort to operation cancellation, so terminating an HTTP/CLI client does not establish that the daemon-side mutation stopped. [Lifecycle inventory](https://github.com/cashubtc/coco/blob/44e5101cbea370132af6e68f88e01b47e39431c4/packages/cocod/src/v1/http.ts#L120), [routes](https://github.com/cashubtc/coco/blob/44e5101cbea370132af6e68f88e01b47e39431c4/packages/cocod/src/routes.ts#L95), [CLI envelope handling](https://github.com/cashubtc/coco/blob/44e5101cbea370132af6e68f88e01b47e39431c4/packages/cocod/src/cli-shared.ts#L281).

Coco core does provide native `ops.send.get/listPrepared/listInFlight/refresh`, recovery, cancel/reclaim/finalize, and analogous receive get/list/refresh/recovery/cancel. Reads of stored operations are distinct from refresh/recovery, which can contact the mint and update state. Send refresh checks original proof states and finalizes only when its native decision permits; default handling leaves unresolved sends pending. **These are library methods, not exposed cocod CLI/HTTP routes at this pin.** Do not advertise them as callable daemon endpoints or inject another manager into the live database. [SendOpsApi](https://github.com/cashubtc/coco/blob/44e5101cbea370132af6e68f88e01b47e39431c4/packages/core/api/SendOpsApi.ts#L55), [ReceiveOpsApi](https://github.com/cashubtc/coco/blob/44e5101cbea370132af6e68f88e01b47e39431c4/packages/core/api/ReceiveOpsApi.ts#L33), [native pending decision](https://github.com/cashubtc/coco/blob/44e5101cbea370132af6e68f88e01b47e39431c4/packages/core/operations/send/SendOperationService.ts#L716).

The running manager already enables proof-state watchers; session creation recovers send, melt, receive and mint operations. Receive recovery is reached through the payment-request recovery service. Thus native session restart/unlock is an active recovery boundary, not a passive “check.” Prefer observing existing history/watcher progress first. Any deliberate recovery lifecycle change requires exclusive ownership and subsequent observations. [Manager startup](https://github.com/cashubtc/coco/blob/44e5101cbea370132af6e68f88e01b47e39431c4/packages/core/Manager.ts#L220), [receive recovery call](https://github.com/cashubtc/coco/blob/44e5101cbea370132af6e68f88e01b47e39431c4/packages/core/services/PaymentRequestReceiveService.ts#L391).

History is the exposed reconciliation evidence. Send entries include operationId/state and a token when retained; receive history is projected only for finalized/rolled-back operations and finalized entries can include the original input proofs. In-flight receive absence from history is therefore **not proof that it never started**. Never log the raw history/event response. A retained token-bearing send entry may permit exact export recovery after private correlation; the route does not promise byte-for-byte re-emission of the original encoded string. [Send history projection](https://github.com/cashubtc/coco/blob/44e5101cbea370132af6e68f88e01b47e39431c4/packages/core/models/History.ts#L187), [receive history projection](https://github.com/cashubtc/coco/blob/44e5101cbea370132af6e68f88e01b47e39431c4/packages/core/models/History.ts#L250).

## Ambiguous transport outcomes

1. Reserve private capture/delivery capacity before native export. Retain the owned execution and exact private bytes; transport acceptance, recipient invocation and wallet redemption are separate records.
2. After an uncertain export, do not generate another token. CDK has native saga recovery but no exact export lookup CLI; cocod has private native history with the limits above. If exact correlation fails, report unknown.
3. After an uncertain import, observe native recipient history/balance and sender native recovery/watcher state. Resume wallet-owned recovery where exposed; do not replay the token solely because a client timed out. Cocod's HTTP JSON body is a real native import binding for private file/body delivery, but the handler materializes JSON/token in memory—it is not unlimited streaming.
4. NUT-07 SPENT means the proof was redeemed at the mint; PENDING is in-flight and UNSPENT remains spendable at that observation. None identifies which recipient redeemed it or proves a transport delivery exactly once. Bind sender proof identity to the intended recipient's native receipt/history and balance. These semantics explain existing native recovery; they do not justify a duplicate raw NUT-07 implementation. [Primary NUT-07](https://github.com/cashubtc/nuts/blob/main/07.md).

The immediate reusable bindings are CDK native send/receive plus deliberate native saga/pending recovery, and cocod native send/receive HTTP plus private history and existing daemon recovery. The remaining interface gaps are bounded large-token CDK input, explicit per-operation cocod reconciliation exposure, and reliable exact correlation after lost native responses. Do not convert any of these gaps into fabricated success or wallet-specific top-level Proofstorm mutation tools.
